SEC.01 // WHAT IS MIDNIGHT

Overview概览

Midnight is a blockchain platform for building privacy-preserving DApps. Per the docs: it "enables developers to define how data is isolated, verified, and shared through zero-knowledge (ZK) proofs and programmable confidentiality controls." It is a proof-of-stake, Substrate-based chain and the first partner chain to Cardano, with a native Cardano bridge. Smart contracts are written in Compact, a TypeScript-like DSL; each contract call is proven with a zk-SNARK — compact proofs (~128 bytes) verified in milliseconds regardless of computation complexity.

Midnight 是构建隐私保护 DApp 的区块链平台：开发者通过零知识证明（ZK proofs）和可编程的保密控制来定义数据如何被隔离、验证与共享。它是基于 Substrate 的 PoS 链，也是 Cardano 的第一条 partner chain（伙伴链），自带 Cardano 桥。智能合约用类 TypeScript 的 DSL —— Compact 编写；每次合约调用都由 zk-SNARK 证明（约 128 字节，毫秒级验证，与计算复杂度无关）。

Defining properties关键特性

  • Dual state — public state on-chain; private state stays encrypted on the user's machine, accessed only through witness functions. 双态模型：公共状态上链，私有状态加密留在用户本机，仅通过 witness 函数访问。
  • Dual ledger — shielded (private) and unshielded (public) tokens coexist; assets can transition between the two. 双账本：shielded（私密）与 unshielded（公开）代币并存，可互相转换。
  • Rational privacy — shielding is opt-in; viewing keys grant read-only access to shielded transactions for compliance. 理性隐私：屏蔽是可选的；viewing key 为合规提供只读访问。
  • Local proving — a local proof server generates all ZK proofs, so private data never leaves the user's machine. 本地证明：proof server 在本地生成全部 ZK 证明，私有数据不出本机。
  • Dual-component tokenomics — NIGHT (transferable utility token) generates DUST (non-transferable fee resource), decoupling validator rewards from fee volatility. 双组件代币经济：NIGHT（可转让）生成 DUST（不可转让的手续费资源），把验证者激励与手续费波动解耦。

Key papers cited by the docs: Kachina (eprint 2020/543) · Zswap (eprint 2022/1002, PoPETs 2022) · Zerocash (IEEE S&P 2014) · PoS Sidechains (eprint 2018/1239). Whitepapers: Nightpaper + Tokenomics Incentives at midnight.network/whitepaper.

2.3 Transaction anatomy交易结构

A transaction contains a guaranteed Zswap offer, an optional fallible Zswap offer, an optional contract-calls segment, and binding randomness. Fees are collected in the guaranteed phase; a fallible-phase failure keeps guaranteed effects and forfeits fees. Integrity comes from homomorphically summed Pedersen commitments plus a Fiat–Shamir Schnorr proof. 交易由 guaranteed（保证段）Zswap offer、可选 fallible（可失败段）offer、可选合约调用段与绑定随机数组成。手续费在保证段收取；可失败段失败时保证段效果仍生效、费用不退。完整性由同态求和的 Pedersen 承诺 + Fiat–Shamir Schnorr 证明保证。

2.5 Contract execution model合约执行模型

Three execution environments: ledger (public, on-chain), circuit (proof logic), witness (private, off-chain). A call produces a public transcript plus a ZK proof that the transcript is correct; the on-chain verifier key checks it. 三个执行环境：ledger（公开、链上）、circuit（证明逻辑）、witness（私有、链下）。一次调用产出公共 transcript + 证明其正确性的 ZK proof，由链上 verifier key 验证。

SEC.03 // HOW MIDNIGHT WORKS

Core Concepts核心概念

Kachina智能合约模型

Kachina is "a data-protecting smart contract model that enables confidential, general-purpose smart contract functionality without sacrificing decentralization." Contracts are reactive state machines with public state (blockchain) and private state (user machine), connected by ZK proofs that private state changes justify public state changes. Kachina 是数据保护型智能合约模型：合约是响应式状态机，公共状态在链上、私有状态在用户本机，二者由 ZK 证明连接——证明私有状态的变化能正当化公共状态的变化。

Zswap屏蔽代币机制

Zswap is "a shielded token mechanism, based on Zerocash, extended with native token support and atomic swaps" (combining Zcash and SwapCT). An offer = inputs (spends) + outputs + transient coins (created and spent in the same tx) + a balance vector over all token types. Outputs create commitments in a global Merkle tree; inputs reveal unlinkable nullifiers that prevent double-spends. A token type is a 256-bit hash derived from contract address + domain separator (zero = native token). Two transactions can merge into an atomic swap when at least one has no contract calls. Zswap 基于 Zerocash，扩展了原生代币与原子交换。Offer = 输入（花费）+ 输出 + transient coin（同笔交易内创建并花掉）+ 覆盖所有代币类型的余额向量。输出在全局 Merkle 树写入 commitment；输入揭示不可关联的 nullifier 防双花。Token type 是合约地址 + 域分隔符派生的 256 位哈希（零值 = 原生代币）。当至少一方没有合约调用段时，两笔交易可合并为原子交换。

Impact VM链上虚拟机

Impact is "a stack-based, non-Turing-complete state manipulation language." Users cannot write Impact manually; it is still under active revision. State values (immutable to the program): null, cell, Map, Array(n) with 0<n<16, MerkleTree(d) with 1≤d≤32. Values use Field-Aligned Binary (FAB) encoding so they can re-encode as field elements in any prime field. A transcript binds gas bound + declared effects + program; declared effects are verified against actual execution. Impact 是基于栈、非图灵完备的状态操作语言，用户不能手写，仍在迭代。状态值（程序视角不可变）：null、cell、Map、Array(n)（0<n<16）、MerkleTree(d)（1≤d≤32）。值采用 FAB（域对齐二进制）编码。Transcript 绑定 gas 上限 + 声明的 effects + 程序，声明与实际执行相互校验。

Privacy patterns隐私模式

The commitment/nullifier pattern acts as a single-use authentication token: commit a value into a MerkleTree publicly ("some value is in the tree, without revealing which"), then spend it once by publishing its nullifier into a Set. persistentHash/persistentCommit put private data on the public ledger without revealing content; HistoricMerkleTree accepts proofs against prior tree versions. Commitment/nullifier 模式 = 一次性认证令牌：先把值承诺进 MerkleTree（可证明「树里有某值」而不暴露是哪一个），花费时把 nullifier 写入 Set 防重用。persistentHash / persistentCommit 让私有数据以不可逆形式上链；HistoricMerkleTree 接受针对历史版本树根的证明。

Ledger state账本状态

Ledger state = Zswap state (coin-commitment Merkle tree, first-free index, nullifier set, valid historical roots) + a contract state map from address to Impact state value plus an entry-point→operation map, where each operation stores a SNARK verifier key. Contract deployment "creates a new contract if it does not already exist and fails otherwise"; the address is a hash of the deploy part. 账本状态 = Zswap 状态（币承诺 Merkle 树、首空位索引、nullifier 集合、有效历史根）+ 合约状态映射（地址 → Impact 状态值 + 入口点→操作映射，每个操作存 SNARK verifier key）。部署仅当合约不存在时成功；地址是部署段的哈希。

Consensus & node internals共识与节点内部

AURA (proof-of-authority, round-robin slots) produces blocks every 6 s; GRANDPA provides asynchronous provable finality (~18 s). Cardano SPOs delegate stake to Midnight's permissioned validators. Runtime logic compiles to WASM (the state transition function); pallet-midnight processes proof-validated, unsigned ledger transactions; canonical state lives in a Patricia-Merkle trie persisted by ParityDB. Crypto: Blake2-256 (hashes), Sr25519 (AURA), Ed25519 (GRANDPA + libp2p), ECDSA (partner-chain messages). P2P: libp2p with Kademlia DHT, Noise encryption, Yamux multiplexing, port 30333. AURA（PoA 轮询出块，6 秒）+ GRANDPA（异步可证明最终性，约 18 秒）。Cardano SPO 将质押委托给 Midnight 的许可制验证者。运行时编译为 WASM；pallet-midnight 处理经证明验证的无签名账本交易；规范状态存于 Patricia-Merkle trie（ParityDB 持久化）。密码学：Blake2-256 / Sr25519 / Ed25519 / ECDSA。P2P：libp2p + Kademlia DHT + Noise + Yamux，端口 30333。

Current limits当前限制

  • Cross-contract calls within circuits are not yet supported ("cross-contract calls are not yet supported" — compiler error). 电路内跨合约调用暂不支持。
  • DApps requiring oracles (e.g. price feeds) cannot be built yet. 依赖预言机的 DApp 暂不可行。
  • Solidity cannot be reused — TypeScript + Compact only. 不能复用 Solidity，只有 TypeScript + Compact。
  • "The details of Midnight's native currency implementation are not yet stable." 原生货币实现细节尚未稳定。

SEC.04 // DUAL-COMPONENT TOKENOMICS

Token Model代币模型

Docs analogy: "NIGHT: Analogous to a Solar Panel… DUST: Analogous to Electricity." 官方类比：NIGHT 像太阳能板，DUST 像它发的电。

Aspect维度NIGHTDUST
Definition定义 "The unshielded utility token used for staking, securing the network, and governance." Transferable, persistent.非屏蔽效用代币：质押、网络安全、治理；可转让、持久。 "A shielded, non-transferable resource that the network consumes to pay transaction fees." Explicitly not a token.屏蔽、不可转让的资源，网络消耗它支付手续费；明确不算代币。
Atomic unit最小单位 Star — 1 NIGHT = 106 Stars Speck — 1 DUST = 1015 Specks
Variants形态 cNIGHT (on Cardano) · mNIGHT (future native) · tNIGHT (testnet faucet) tDUST (testnet) · generated, never bought只能生成，不能购买
Role角色 Validator rewards stay predictable — decoupled from fee volume.验证者奖励可预测，与手续费量解耦。 Every transaction consumes DUST; equilibrium via burn-and-mint cycles.每笔交易消耗 DUST；通过燃烧-铸造循环维持均衡。

DUST generationDUST 生成机制

A DUST UTXO is created iff a NIGHT UTXO is created and the owner has a Registration Table entry linking NIGHT public key → DUST public key. Value is lazily evaluated at spend-time. Initial parameters: cap 5 DUST per NIGHT (ratio 5,000,000,000); generation/decay rate 8,267 ≈ 1 week to cap; grace period 3 hours. Spending is a 1-to-1 self-transfer: one input UTXO (nullifier) → one output UTXO worth value − gas. 当且仅当 NIGHT UTXO 创建且所有者在 Registration Table 里登记了 NIGHT 公钥 → DUST 公钥映射时，才会生成 DUST UTXO。价值在花费时惰性计算。初始参数：上限 5 DUST/NIGHT；约 1 周到顶；宽限期 3 小时。花费是 1 对 1 自转账：1 个输入（nullifier）→ 1 个输出（价值减去 gas）。

Cross-chain timing: cNIGHT registration finalizes on Cardano then reaches a Midnight node in ~12 hours; local networks generate DUST in ~5 minutes. The Native Token Observation Pallet watches cNIGHT events on Cardano and updates DUST supply 1:1. 跨链时序：cNIGHT 注册需先在 Cardano 最终化再传到 Midnight 节点，约 12 小时；本地网络约 5 分钟。Native Token Observation Pallet 监听 Cardano 上的 cNIGHT 事件，1:1 更新 DUST 供应。

Shielded vs unshielded tokens屏蔽与非屏蔽代币

Four quadrants: {shielded, unshielded} × {ledger tokens (protocol-managed UTXOs, e.g. NIGHT), contract tokens (account-style, ERC-20-like, managed in Compact)}. Unshielded token balances are chain-resident and publicly readable via unshieldedBalance(color). A shielded token "has no public balance to read, its value lives in immutable coins" — the chain tracks only commitments and nullifiers; partial transfers create change coins via deterministic nonce evolution (evolveNonce()). Token standards discussion: Midnight Improvement Proposals #142. 四象限：{屏蔽, 非屏蔽} × {账本代币（协议管理的 UTXO，如 NIGHT）, 合约代币（账户式，类 ERC-20）}。非屏蔽余额链上可读；屏蔽代币没有公开余额，价值存在不可变的 coin 里——链上只记录 commitment 与 nullifier；找零通过确定性 nonce 演化生成新 coin。

SEC.05 // LANGUAGE 0.23.0 · COMPILER 0.31.x

Compact Language语言参考

Contract anatomy合约构成

pragma language_version 0.23;
import CompactStandardLibrary;

export enum State { VACANT, OCCUPIED }
export sealed ledger authority: Bytes<32>;   // sealed: constructor-only writes
ledger round: Counter;
witness secretKey(): Bytes<32>;              // implemented in TypeScript

constructor(pk: Bytes<32>) { authority = disclose(pk); }

export circuit act(): [] {                    // export circuit = entry point
  const pk = publicKey(round as Bytes<32>, secretKey());
  assert(disclose(pk) == authority, "not authorized");
  round.increment(1);
}
circuit publicKey(r: Bytes<32>, sk: Bytes<32>): Bytes<32> {
  return persistentHash<Vector<3, Bytes<32>>>(
    [pad(32, "midnight:examples:lock:pk"), r, sk]);
}
  • circuit — compiled to a ZK circuit; no recursion, bounded loops, fixed-size types. pure circuit = no ledger/witness/impure calls. 编译为 ZK 电路；禁递归、循环有界、类型定长。
  • witness — declared in Compact, implemented in TypeScript; results are untrusted input, verify in-circuit. Compact 声明、TypeScript 实现；返回值是不可信输入，必须在电路内验证。
  • disclose() — compile-time annotation authorizing witness-derived data to cross visibility boundaries (ledger writes, exported returns, cross-contract). No runtime effect. The checker ("witness protection program") is an abstract interpreter tracking data flow; transientCommit output is exempt, transientHash output is not. 编译期标注，授权 witness 数据跨越可见性边界；无运行时效果。检查器是追踪数据流的抽象解释器；transientCommit 的输出豁免，transientHash 的不豁免。
  • sealed ledger — field writable only from the constructor. 仅构造函数可写。

Security patterns安全模式

// Canonical nullifier pattern (from docs, verbatim)
export ledger usedNullifiers: Set<Bytes<32>>;
circuit nullifier(secretKey: Bytes<32>): Bytes<32> {
  return persistentHash<Vector<2, Bytes<32>>>([pad(32, "nullifier-domain"), secretKey]);
}
export circuit spend(secretKey: Bytes<32>): [] {
  const nul = nullifier(secretKey);
  assert(!usedNullifiers.member(nul), "Already spent");
  usedNullifiers.insert(disclose(nul));
}
  • Privacy by default; place disclose() as close to the disclosure point as possible. 默认隐私；disclose() 尽量靠近披露点。
  • Never trust witness outputs — verify cryptographically in-circuit. 永不信任 witness 输出，必须在电路内密码学验证。
  • Domain-separate every hash (pad(32, "nullifier-domain") vs "commitment-domain"); never reuse commitment salts. 所有哈希做域分隔；承诺盐值不复用。
  • Generic error messages — no private data in asserts. 报错信息不携带私有数据。

Developer Workflow开发工作流

SEC.11 // TERMINOLOGY — AS DEFINED BY THE DOCS

Glossary术语表

Terms preserved exactly as the docs define them (official /glossary page + canonical definitions from concept pages, deduplicated). EN definition first, ZH translation follows. 术语名保持文档原文；英文释义在前，中文翻译在后。

Platform & protocol平台与协议

Kachina
"A unified security model for data-protecting smart contracts that bridge the gap between private state on the user's local machine and public state on the blockchain."连接用户本机私有状态与链上公共状态的数据保护型智能合约安全模型。
Zswap
"A transaction scheme that combines the strengths of Zcash and SwapCT" — shielded multi-asset tokens with atomic swaps.结合 Zcash 与 SwapCT 的交易方案：屏蔽多资产 + 原子交换。
Impact
Stack-based, non-Turing-complete on-chain state manipulation language (the VM); not hand-writable.基于栈、非图灵完备的链上状态操作语言（VM），不可手写。
Partner chain
A chain inheriting security from an established layer; Midnight is the first partner chain to Cardano.从成熟链继承安全性的链；Midnight 是 Cardano 首条伙伴链。
Firewall property
"The failure of one ledger must not endanger the security of other connected ledgers."一条账本的失败不得危及相连账本的安全。
AURA / GRANDPA
PoA round-robin block production / asynchronous provable finality gadget.PoA 轮询出块 / 异步可证明最终性。
pallet-midnight
"The core pallet powering Midnight's privacy-preserving transaction logic."驱动隐私交易逻辑的核心 pallet。
Runtime upgrade
Evolving a Substrate chain by storing the state-transition code on-chain and updating it via dedicated transactions.链上存储并升级状态转换代码的机制。
Guaranteed / fallible phase
Two-phase execution: guaranteed must succeed for inclusion (fees collected here); fallible failure keeps guaranteed effects.两段执行：保证段失败则交易不上链；可失败段失败时保证段效果仍生效。
Transcript
The declared record of a call's visible effects — gas bound + effects + program; verified against actual execution.调用可见效果的声明记录（gas 上限 + effects + 程序），与实际执行相互验证。
System transaction
Governance-gated, root-origin state change; not user-submittable.治理提交的根权限状态变更。
Universally Composable (UC)
"A theoretical framework used to analyze and prove the security of cryptographic protocols in a composable manner."以可组合方式证明密码协议安全性的理论框架。

Cryptography密码学

Zero-knowledge proof (ZKP)
"Allows someone to prove they know a secret without revealing the secret."在不泄露秘密的前提下证明知道该秘密。
ZK-SNARK
Succinct non-interactive argument of knowledge; ~128-byte proofs, millisecond verification, size independent of computation.简洁非交互知识论证：约 128 字节、毫秒验证、与计算量无关。
ZK circuit
"Arithmetic circuits are short programs consisting of a fixed number of multiplications and additions in a modular prime field."素域上由固定数量乘加构成的算术电路。
Witness (logic)
"In mathematical logic, a witness is a value that satisfies an assertion" — in Midnight: the prover's private input.满足断言的值；在 Midnight 中即证明者的私有输入。
Commitment
"Allows a party to commit to a chosen value while keeping it hidden" — binding and hiding.对选定值作出既绑定又隐藏的承诺。
Nullifier
"A unique value derived from a coin or private state element that is revealed on-chain when that element is consumed" — prevents double-spends, unlinkably.消费时链上揭示的唯一值，不可关联地防止双花。
Pedersen commitment
Homomorphic commitment scheme (Pedersen, 1992); summed across a transaction for balance integrity.同态承诺方案，用于交易余额完整性。
Blinding factor
"A random value used in cryptographic commitment schemes … to hide the underlying data."承诺方案中用于隐藏数据的随机值。
Proving / verification key
Per-circuit artifacts from the SNARK setup: large prover key generates proofs; compact verifier key checks them on-chain.每电路一对：大的证明密钥生成证明，小的验证密钥在链上校验。
Halo 2
"A high-performance ZK Snark implementation from the Electric Coin company."Electric Coin 公司的高性能 SNARK 实现。
Midnight SRS
Structured Reference String introduced in Ledger 7.0.0 — invalidated all prior proofs and verifier keys.Ledger 7.0.0 引入的结构化参考串，使所有旧证明失效。
Jubjub curve
"Midnight's native internal curve" — in-circuit EC ops and Schnorr signatures (JubjubPoint).Midnight 电路内原生曲线。
Selective disclosure
"Allows a user to reveal only a specific subset of their personal data or attributes to a verifier."只向验证方披露所需的最小数据子集。
Viewing key
Read-only access to shielded transactions (compliance); also the indexer session credential.对屏蔽交易的只读访问；亦用于 indexer 会话。

Tokens & state代币与状态

NIGHT
"Midnight's native utility token, transferable and persistent, used for governance, incentives, and as the source of DUST generation."原生效用代币：可转让、持久，用于治理、激励，并生成 DUST。
DUST
"A shielded, non-transferable, consumable network resource used exclusively to pay transaction fees on Midnight."屏蔽、不可转让、消耗性的网络资源，专用于支付手续费。
STAR / SPECK
Atomic units: 1 NIGHT = 10⁶ STAR; 1 DUST = 10¹⁵ SPECK.最小单位。
cNIGHT / mNIGHT / tNIGHT / tDUST
NIGHT on Cardano / future native NIGHT on Midnight / testnet NIGHT / testnet DUST (no real-world value).Cardano 形态 / 未来原生形态 / 测试网形态。
Registration Table
On-chain mapping NIGHT public key → DUST public key; prerequisite for DUST generation.NIGHT 公钥到 DUST 公钥的链上映射，DUST 生成的前提。
Shielded / Unshielded
Shielded: "interactions occur without metadata leakage." Unshielded: addresses and amounts visible on the public ledger.屏蔽：交互无元数据泄漏；非屏蔽：地址与金额公开可见。
Ledger / Contract tokens
Protocol-managed UTXOs on-chain vs account-style tokens managed inside Compact contracts (ERC-20-like).协议管理的 UTXO 代币 vs 合约内账户式代币。
Token type / color
256-bit hash derived from contract address + domain separator; zero = native token.合约地址+域分隔符派生的 256 位标识；零值为原生代币。
Qualified coin
"A coin registered in the ledger's commitment Merkle tree with a known index and so qualified to be spent."已入承诺树、有索引、可花费的 coin。
Transient coin
"Coins that are both created and spent in the same transaction."同一交易内创建并花掉的 coin。
Transaction balancing
"If a wallet receives a transaction that is not balanced, the wallet balances [it] by providing necessary inputs and outputs" (+ DUST fees).钱包补足输入输出与手续费使交易平衡。
UTXO
Unspent Transaction Output — a discrete digital coin; Midnight marks spends via a nullifier set.离散数字硬币；Midnight 用 nullifier 集合标记花费。
Blockchain space tokenization
Tokenized transaction capacity — pay in advance for regular inclusion.代币化区块空间，预付以保证交易定期上链。

Development开发

Compact
"The domain-specific language, based on TypeScript, in which Midnight's smart contracts are expressed."基于 TypeScript 的 Midnight 智能合约领域专用语言。
Circuit (Compact)
Exported Compact function compiled to ZK proof logic; proven locally, verified on-chain without revealing private inputs.编译为 ZK 证明逻辑的合约函数：本地证明、链上验证、不泄露私有输入。
Witness (Compact)
Function declared in Compact, implemented in TypeScript; supplies private data at proving time; untrusted.Compact 声明、TS 实现，在证明时提供私有数据；不可信输入。
disclose()
Compiler directive marking witness-derived values as intentionally safe to expose; no runtime effect.标记有意公开 witness 数据的编译器指令；无运行时效果。
Private oracle
"The set of witness functions and the private state over which they operate constitute the private oracle for a contract."witness 函数集合及其操作的私有状态。
Private / public state
Stored locally on the user's device, never published / stored on-chain, visible to all.本机存储永不发布 / 链上存储全网可见。
Derived state
Client-side computation combining public + private state (e.g. isOwner).客户端合成态（公有+私有）。
ZKIR
"Zero-Knowledge Intermediate Representation. A low-level format that Compact smart contracts are compiled into" — the bridge to the ZK backend.Compact 编译产物的低层中间表示，通往 ZK 后端的桥。
Proof server
"A local service that generates zero-knowledge proofs on behalf of a user's DApp" (Docker, port 6300).本地 ZK 证明服务（Docker，6300 端口）。
Midnight Indexer
"A component that follows the Midnight chain to index events and data in a queryable database" (GraphQL v4).跟链索引事件与数据的可查询服务。
DApp connector
"A software interface that allows a DApp … to communicate with a user's Web3 wallet" — window.midnight.{walletId}.DApp 与钱包通信的浏览器接口。
MidnightProviders
The six-provider configuration object midnight-js requires: private state, public data, ZK config, proof, wallet, midnight.midnight-js 所需的六 provider 配置对象。
Contract maintenance authority
Committee empowered to replace verifier keys/circuits post-deploy; empty committee + threshold 1 = immutable.可替换验证密钥/电路的委员会；空委员会即永久不可变。
Contract address
"A unique identifier assigned to a smart contract when it is deployed" — hash of the deploy part.部署时分配的唯一标识（部署段哈希）。
Domain separator
Hash-input prefix ensuring a value/signature from one context cannot be reused in another.哈希前缀，防止跨场景重放/碰撞。
persistentHash / persistentCommit
SHA-256-based, upgrade-stable hash/commitment for long-lived state.跨升级稳定的哈希/承诺，用于长期状态。
transientHash / transientCommit
Circuit-efficient hash/commitment, not guaranteed stable across upgrades.电路高效但不保证跨升级稳定。
Gadget
"A specialized entry point, specific to zero-knowledge cryptography, designed to bring ZK Snark circuit development within reach."降低 ZK 电路开发门槛的专用入口。
Bech32m / HRP
Address encoding with a human-readable prefix identifying type + network (mn_addr_…, mn_shield-addr_…, mn_dust_…).带可读前缀的地址编码。
HD wallet
Hierarchical Deterministic wallet from one master seed; Midnight path m/44'/2400'/account'/role/index.单种子分层确定性钱包，coin type 2400。
Three-wallet model
WalletFacade coordinating unshielded (NIGHT) + shielded + DUST wallets from one seed.一个种子协调三种钱包。
Faucet
"A web service that distributes free test tokens to developers building on a testnet."测试网免费代币发放服务。
Devnet / Testnet / Mainnet
Development network / intermediate test network (Preview, Preprod) / production chain.开发网 / 测试网（Preview、Preprod）/ 主网。
Attestation
Trusted third-party signature over private data (Schnorr on Jubjub), verifiable inside a ZK circuit.第三方对私有数据的签名，可在电路内验证。
Sealed ledger value
Ledger value unchangeable after constructor execution.构造后不可更改的账本值。
NATS
"A lightweight, high-performance, open-source messaging system" (indexer infrastructure).indexer 使用的轻量消息系统。
Federated Node Operators (FNO)
"A network of independent node operators that work together to maintain and secure the Midnight blockchain."共同维护网络的独立节点运营者联盟。
Midnight Expert
Suite of Claude Code plugins with compiler-verified output for Midnight development.用真实编译器验证输出的 Claude Code 插件套件。
